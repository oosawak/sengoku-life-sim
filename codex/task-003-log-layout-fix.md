## 背景: 大澤のフィードバック（2026-11-01、第1弾を実際に遊んでの指摘）

現状の生涯画面は、ログがページの中にそのまま積み上がっていく作りになっている。このため:

- イベントが発生しても、画面を一番下までスクロールしないとイベントが見えない
- ログが増えるほどページが縦に伸びて、遊びにくい

## やること: 生涯画面の並びとスクロールの分離

対象は生涯画面（`index.html` / `style.css` / 必要なら `app.js` の表示まわり）。表紙・出生札・最期と列伝の画面は変えない。

1. **並び順を固定する**: 上から「常時表示（年月・年齢・能力・評判・所持金・健康）」→「操作（方針・速度）」→「イベント表示（本文と選択肢）」→「ログ」の順にする。イベント表示はログより上に置く。
2. **ログは専用のスクロール領域にする**: ログはページ全体を伸ばさず、決まった高さの領域の中でだけスクロールさせる（`overflow-y: auto` 相当）。新しいログが増えたら、領域の中だけを最下部へ自動で追従させる。ページ自体のスクロールでは追いかけない。
3. **イベント発生時に、画面スクロールなしでイベントが見えること**: 生涯画面は原則として画面の高さ（100dvh 目安）に収まるレイアウトにし、イベント本文と選択肢が常に見える位置に来るようにする。小さい画面でイベント本文が長い場合は、イベント領域側に最小限の配慮をしてよいが、選択肢にたどり着くためにページ全体を大きくスクロールさせる作りにはしない。
4. 既存の色づかい（紙色・朱色）と文言は維持する。仕組み（月進行・成長・収入・設定）には手を入れない。

## やらないこと

- 仕組みの変更（このタスクはレイアウトだけ）
- 他の画面（表紙・出生札・列伝）のレイアウト変更
- データ（人物・イベント）の変更
- SNS等への告知・宣伝

## 検証

- ローカルでHTTP配信し、主要ファイルが200で返ること。
- ログを大量に出してもページが伸びず、ログ領域の中でスクロールすること（ロジックまたは簡易再現で確認し、報告書に方法を書く）。
- イベント発火時にイベント表示が画面内に見える構成になっていること。
- push 後、公開側で新しい版が反映されていること。

このタスクではサイトファイルの変更と main への push（＝そのまま公開）を許可する。

## 報告書の形式

`reports/2026-11-01-task003-log-layout.md`（日付は完了日に合わせてよい）に:

- 直した内容（レイアウトの変更点）
- 検証の方法と結果（公開側の確認を含む）
- 触らなかった範囲の確認

## 完了の条件

- 修正が commit・push され、公開ページで新しい版が動いている
- 報告書が `reports/` に置かれている
- このファイルの末尾に「状態: 完了（報告: reports/＜報告書ファイル名＞）」を追記する
