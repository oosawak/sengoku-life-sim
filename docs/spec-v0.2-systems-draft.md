# 戦国人生シミュレーション v0.2 ゲームシステム設計（叩き台）

作成: 2026-11-01  
位置づけ: 実装前の設計案。記載する数値はすべて仮案で、実プレイの試行後に調整する。  
対象: 月進行、成長、経済、日常イベント、判定、健康・寿命の基礎ルール。合戦の3D化と正式タイトルは扱わない。

## 設計の前提

- v0.1 の「人物データの基準能力値」「年月順の専用イベント」「評判・寿命・flag の effect」を活かし、プレイヤーが生涯に繰り返し選択する判断を追加する。
- ゲーム内時間は月単位。史実イベントは既存の `year` に `month` を加えた年月で発火する。`month` のない既存イベントは互換のため1月扱いとする案。
- 数値は読みやすさと短いプレイを優先するゲーム上の単位。実在人物の史実値、史料上の禄高を表すものではない。人物・イベントの既存の史実内容は変更しない。
- 出来事が発生した月は時間を止めて選択を求める。再生速度は出来事の確認・選択時間を短縮しない。

## 1. 時間と速度

### 進行単位と速度案

1年を12か月とし、誕生月は全員1月として年齢を年単位で表示する案。内部状態は `year` と `month`（1〜12）で持ち、各月の順に「月初の収入 → 方針の効果 → 健康・寿命処理 → その年月のイベント抽選と発火」を行う。特定月の史実イベントはランダム抽選より先に処理し、同年月は `priority`、次いで `id` で安定ソートする。

| 設定 | 1か月あたりの実時間（案） | 70年＝840か月の無操作換算 |
|---|---:|---:|
| 停止 | 進行なし | — |
| ×1 | 240ms | 約202秒（3分22秒） |
| ×5 | 48ms | 約40秒 |
| ×10 | 24ms | 約20秒 |
| ×20 | 12ms | 約10秒 |

`setInterval` の遅延やブラウザーのバックグラウンド抑制によって実時間には誤差が出る。ここでいう速度は月を何倍速く処理するかであり、実装では経過時間を蓄積して月を進める方式を推奨する。選択待ち時間は上記換算に含まない。

### プレイ時間の見積もり

イベントで止まっている時間を除けば、史実没年が70年後の人物は×1で約3分20秒、×20で約10秒の機械進行。日常・専用イベントを計50〜75回経験し、選択に平均5秒かかる想定では、選択に約4〜6分加わる。読み込みや考慮時間を含めた1プレイの目安は約7〜12分。イベントを読む人には速度より一時停止・再開の操作が中心になる。

### 年月イベントの互換・境界

- 史実イベントは `year` と `month`（1〜12）を指定する。既存データで `month` 省略時は1月とみなす互換案。ただし実際の年月が不明な既存項目は、実装前にイベント単位で月を決める。
- 同月の専用イベント・共通イベントはすべて順に提示する。選択後に同じ月の次イベントがあれば月を進めず提示する。
- 史実没年の12月までをプレイ対象とする。選択や健康による延命時は翌月へ進める。人物データの `born` / `died` は史実基準として保持する。

## 2. パラメーターの表示と実感

### スマートフォン縦画面案

生涯画面上部に、名前・西暦年月・年齢・身分をまとめた固定ヘッダーを置く。その直下に「武勇・知略・政治・魅力・家柄」の5能力を小さな横棒と数値で2列または縦5行に表示し、評判と所持金（貫）を並べる。画面幅が狭い場合も数値を省かず、イベント本文より上に現在値を常時表示する。成長方針と速度・停止はヘッダーの下に置き、イベント本文と選択肢はログより先に表示する。

能力値は1〜100。家柄は出生時の固定値で、通常の成長方針では変化しない。評判は初期0、上限/下限を設けず累積する案。所持金は0未満にせず、支払い不能な行動は選べないようにする。健康は内部状態として保持し、別途「健やか／不調／重篤」の短い状態表示を設ける案（数値を常時出すかは未決）。

### 増減のフィードバック

- effect 適用直後、対象値の横に `武勇 +2`、`所持金 −1.5貫` のような色付き変化表示を約2秒出す。色だけに依存せず符号・項目名・数値を併記する。
- 増えた能力のバーを短くアニメーションし、下部ログにも年月・理由・変更値を記録する。複数の効果は項目別にまとめて表示する。
- 成長による小数は内部に保持し、画面では整数に丸める。表示値が変わらない端数の期間も、方針の説明に「次の上昇まで」を任意表示する。
- 初期値と現在値を出生札・列伝に残し、「生涯で武勇 +○」を最期に表示する。

## 3. 方針（成長方法）

### 方針候補と月ごとの効果案

プレイヤーはその月の重点を1つ選ぶ。重点を決めない「休養」も用意する。

| 方針 | 主な効果（1か月案） | 費用（1か月案） | 備考 |
|---|---|---:|---|
| 武芸稽古 | 武勇 +0.05 | 0.15貫 | けがリスクを少し上げる余地 |
| 学問 | 知略 +0.05 | 0.12貫 | 書物・師への支払い |
| 政務 | 政治 +0.05 | 0.10貫 | 役職就任後に選択可能とする案 |
| 人付き合い | 魅力 +0.05 | 0.15貫 | 評判 +0.02 を追加する案は要調整 |
| 家の仕事・商い | 所持金 +0.10貫 | 0貫 | 当主・家臣とも選べる共通表現 |
| 休養 | 能力上昇なし | 0貫 | 健康回復の基本手段 |

能力成長の0.05は毎月の期待値。所持金から費用を払えない月は、その方針の訓練を休みに切り替える案。効果は年齢や能力によって減衰する。方針は生涯画面の選択欄からいつでも変更でき、変更に費用や待ち時間は設けない。

### 逓減・成長上限・老齢

基準値からの成長分は能力100で止める。現在値80以上は通常の50%、95以上は25%の上昇量にし、人物の得意能力が早く天井に達するようにする。家柄は成長対象外。能力値は整数に切り捨てず小数蓄積して表示時に丸める。

老齢は70歳から各月の成長を段階的に減らし、80歳で基準量の半分とする案。能力を年齢だけで自動低下させると史実外の人物像を強く変えてしまうため、v0.2では恒常的な能力低下を入れない。老化による健康・回復の不利は健康ルールで扱う。

### バランス目安

0.05を840か月続けた場合、逓減・休養・資金切れを無視した単一能力の上昇上限は42点。史実イベント・成長イベントから得る追加上昇を含めても、平均的な70年プレイの能力合計上昇は約40〜55点（重点能力が主に+25〜35、他能力合計+10〜20）を目安とする。能力合計が出生時から倍になる設計にはしない。

## 4. お金・収入・役職

### 通貨と初期所持金案

画面表示の通貨は **貫** とし、内部では小数1桁（0.1貫単位）まで扱う。1貫＝1000文という便宜上の換算を表示説明に添える。経済は史料再現ではなく、育成費・生活費・報酬を比較するためのゲーム尺度。出生時の所持金は家格により「大名級 20貫、家老級 8貫、国衆 4貫」を案とする。家柄・人物の史実価値を表すものではない。

### 年収案

年収は所属・役職の月初に12等分して支給する。プレイ開始時の初期役職を人物の `rank` から決め、人物の当主/家臣という立場を既存データに追加するまでの仮置きにする。

| 共通段階 | 初期割当の目安 | 年収案 |
|---|---|---:|
| 家中の者 | 国衆・若年の家臣 | 2貫 |
| 侍大将 | 家老級の初期案 | 6貫 |
| 城主・重臣 | 家老の昇進後 | 18貫 |
| 家中筆頭 | 大大名家の重臣など | 36貫 |
| 大名 | 大名級の当主 | 60貫 |

これらは月あたり0.17〜5貫相当で、重点訓練の年間費（約1.2〜1.8貫）を家臣でも賄え、昇進で余裕が生まれるよう置いた仮値。低身分の開始金と年収では商い・節約・評判を選ぶ意味が残るか、実装後に残高推移を見て調整する。

### 出世・身分の扱い

「共通段階＋人物固有の表示名」の折衷案。内部に `rankLevel`（0〜4）を持ち、プレイヤーには人物ごとの役職名を表示する。上昇は年1回の査定で、評判・政治・知略・特定の旗（史実イベントの成果）を用いた条件判定とする。大名級は当主として「大名」段階から開始し、共通の役職昇進ではなく領地・評判上の称号や宿願の進展を目標にする。家臣・国衆は共通段階を上る。人物別の役職辞書や具体的な昇進条件は第2弾で詰め、家臣と当主の道筋を同一の役職列に押し込まない。

役職名は史実の特定の人物に不適切な官位を断定しないよう、初期案では「家中の者／侍大将／城主・重臣／家中筆頭／大名」の抽象名を基本とする。人物固有名を使う場合は事実確認が必要。

## 5. 日常イベント

### 発生頻度案

毎月、日常イベント抽選を独立して行い、基本確率を **3%** とする。確率は月ごとに1回まで。特定カテゴリが連続しないよう、同一イベントの再発は5年（60か月）冷却し、同じカテゴリは3か月連続しないよう重みを下げる。年1回、年齢・役職に合う季節行事候補から定例イベントを抽選する（開催確率55%）。専用史実イベントとは別枠で、同月に重なれば日常イベントは翌月へ繰り越す。

70年の一生では、月抽選の期待値が840×0.03＝約25回、年次抽選が70×0.55＝約39回。合計約64回の暮らしイベントに、平均3〜5件の専用史実イベントを足した **一生約67〜69回** を初期目安とする。実際は没年、イベント候補の条件、冷却、重複月の繰り越しで変わる。日常イベントを優先して読ませたいので、未処理の繰り越しは最大3件までとし、超過分は次の適合機会に再抽選する案。

### カテゴリー・年齢差

- 成長: 師匠との稽古、書物、弓の稽古。能力上昇、費用、けがの選択。
- 金銭: 収穫、商人の出入り、出費、知行の不足。所持金と評判の交換。
- 健康: 発熱、傷、養生、薬師。健康・寿命と費用の交換。
- 人間関係: 家族、主君、同僚、家臣との縁。評判、旗、能力への小さな効果。
- 評判・家中: 村の訴え、家中の揉め事、使者の応対。政治・魅力・評判・査定旗。
- 年齢条件: 0〜6歳は養育・病、7〜14歳は学び・稽古、15〜59歳は婚姻・役目・家中、60歳以降は後継・隠居・養生を重み付けする。

### v0.2 用意する量とイベント案

日常イベント **30件** を初回実装の目標とする。選択肢2つ以上、各選択が最低1つの結果（能力・評判・所持金・健康・flag）を持つ。ひとつのイベントを冷却期間後に再利用可能にすることで、有限の作成量で一生を支える。履歴には年月と選択結果を記録する。

| 件数案 | カテゴリー | 具体例 |
|---:|---|---|
| 6 | 成長 | 弓の稽古、剣術の師、書物の借用、寺での学び、年長者の政務見学、武具の手入れ |
| 5 | 金銭 | 米の売買、商人の提案、家計の見直し、凶作の備え、余剰品の市 |
| 5 | 健康 | 発熱、古傷、薬師の診立て、湯治の誘い、無理な稽古の後の養生 |
| 5 | 人間関係 | 主君への取次、家臣の相談、親族の祝い、同僚との競い合い、使者のもてなし |
| 5 | 評判・家中 | 村の訴え、年貢の相談、城下の火事、家中の口論、寺社への寄進 |
| 4 | 年齢・季節行事 | 元服の祝い、婚姻の縁談、隠居の打診、年始の挨拶 |

災害や武力衝突を軽いランダムイベントとして扱う場合も、既存の史実イベントと矛盾しない抽象的な設定に限る。特定人物の生没・出来事・宿願の事実はこの案を理由に変更しない。

## 6. パラメーター判定

### 固定基準値方式を推奨

能力判定は `能力値 + 修正 >= 難易度` で成功とする。固定難易度なので、同じ能力・同じ選択なら結果が再現され、プレイヤーが成長の手応えを理解しやすい。確率判定は表示されない揺れが判断を覆しやすいため標準にはしない。成功確率表記を後日試す場合も、判定の乱数は保存・共有可能なシードから生成する。

### frontmatter の具体案

既存の `choices` 配列・`text`・`result`・`effect` を残し、判定付きの選択肢だけに `check` を追加する。現行の単純選択肢はそのまま有効。`check` の場合、成功・失敗それぞれの結果文と効果を入れ、外側の `result` / `effect` は重複させない。

```yaml
choices:
  - text: 用水路の普請を引き受け、村と相談して進める
    check:
      stat: 政治
      difficulty: 62
      modifier: 0
      success:
        result: 村々が協力し、収穫を安定させた。
        effect: { 政治: 1, 評判: 3, 所持金: -0.5 }
      failure:
        result: 見積もりが甘く、普請は途中で止まった。
        effect: { 評判: -2, 所持金: -0.5 }
```

- `stat`: `武勇` / `知略` / `政治` / `魅力` のいずれか。`家柄` は固定能力なので判定対象外。
- `difficulty`: 1〜100の固定難易度。平易55、標準65、難しい75、宿願に関わる高難度85を設計上の目安とする。
- `modifier`: 省略時0、年齢・負傷・役職などの一時補正。具体的な補正ルールは実装時に限定列挙する。
- `success` / `failure`: それぞれ必須の `result` と任意の `effect`。`effect` は既存の評判・寿命・flagに加えて能力名、所持金、健康を許す。

選択肢に `check` がある場合は既定の能力値を参照して一度判定し、成否に応じて文・effectを適用する。判定値はUIで「政治 68 vs 難易度62」のように開示する。v0.2の初期データは判定付きイベントを6件程度に抑え、各能力を最低1件使う。

### 検証ルール案

build.py は `check.stat`、`difficulty` の範囲、success/failure の必須 result、effect の許可キーと数値型を検証する。従来選択肢は従来どおり text/result 必須。判定付きでは結果文が分岐内にあるため、外側 `result` がなくてもよい。互換のため旧形式を許容しつつ、`check` と外側 `result` が両方ある場合は警告を出す。

## 7. 健康と寿命

### 健康の内部値と自然経過案

健康を0〜100（開始100）で管理する案。生涯画面では数値より「健やか（70〜100）／不調（40〜69）／重篤（1〜39）」の状態を優先表示する。0になった時点で死亡処理に入る。毎月は健康を自然減衰させず、70歳から年齢リスクを少しずつ上げる。病気・怪我イベントや無理な稽古で減り、休養・治療で回復する。

健康0で死亡しても史実没年は基準線として尊重し、史実没年より早い死亡は史実イベントや明確な危険選択による場合に限る案。健康由来の早死に判定は、史実没年以降、毎月「年齢と健康から計算した危険度」で行う。健康80以上は月0.3%、50〜79は1.0%、1〜49は2.5%を基礎に、年齢70歳以降は10年ごとに+0.5ポイントする案。数値は早期の試行用で、実装前に乱数と史実寿命との整合をレビューする。

### 史実没年・延命・日常イベントとの接続

- 史実没年の12月が基準の最終月。12月処理後に生存していれば、寿命修正 `寿命` があればその年数分だけ基準を延ばす。修正がなければ年末に自然な最期を迎える。
- 史実没年より前に寿命を延ばす選択を積んでも、基準年までは死亡判定を起こさない。危険な戦闘・病の選択による早死には、イベントの `寿命: -N` または健康0で明示する。
- `effect` の寿命は既存互換で年単位の加減。健康は別キー `健康` で0〜100の範囲に制限。老齢期イベントは健康を軸にし、死亡年の乱数は基準没年の後にだけ適用する。
- v0.2では「病気や怪我で史実没年が前後する」より、明示的な選択・回復と史実没年以降の寿命幅を優先する。死亡を偶然だけで決めない。

## 8. データ形式の変更まとめと実装の段階分け

### 人物 frontmatter の追加案

```yaml
birth_cash: 8.0
starting_rank_level: 1
starting_focus: 学問
health: 100
death_month: 12
```

`birth_cash`、`starting_rank_level`、`starting_focus`、`health`、`death_month` は案。欠落時に rank などから既定値を補完するか、全人物を明示するかは実装判断事項。人物の `born` / `died` と史実注記は変更しない。

### イベント frontmatter の追加・変更案

```yaml
month: 4
category: growth
age_min: 15
age_max: 59
cooldown_months: 60
priority: 50
```

- 日常イベントに `category`、年齢条件 `age_min` / `age_max`、再発間隔 `cooldown_months` を任意で追加。史実イベントでは `year` / `month` を必須にする方向。
- `choices[].effect` の許可先に5能力値、`評判`、`寿命`、`所持金`、`健康` を追加。flagの既存利用を継続。
- 判定は `choices[].check` に能力、固定難易度、成功・失敗の result/effect を持たせる。単純選択は従来の外側 `result` / `effect` 形式を維持。
- 発生頻度の月確率、年次確率、冷却の共通設定はイベント個別データに重複記載せず、ゲーム設定側にまとめる案。

### 実装段階

**第1弾: 生涯の基本ループ**（この指示書の想定範囲）

1. 年月の月進行、停止と×1/×5/×10/×20速度、年月順イベント処理。
2. 生涯画面に5能力・評判・所持金を常時表示し、増減ログと一時表示を追加。

第1弾の前提では日常イベントと詳細な役職出世は無理に含めず、経済・成長の循環を先に確かめる。必要な人物の開始所持金・役職は暫定値を用意する。

**第2弾: 生涯の揺らぎと判定**

1. 日常イベント抽選、冷却、年齢カテゴリ、30件のイベントデータ。
2. 能力判定の `check` データ形式、成功/失敗分岐と検証。
3. 評判・能力・flagに基づく出世と人物別役職表示。
4. 健康、病・怪我、老齢と史実没年以降の寿命幅。
5. 一生の能力成長、現金残高、イベント頻度、所要時間を計測し数値調整。

ゲーム循環の面白さを先に確認できるよう、第2弾は第1弾を遊べる状態にしてから着手する。

## 未決事項（大澤の判断待ち）

1. 誕生月を全員1月とするか、人物ごとの実際の誕生月をデータに加えるか。**推奨案:** v0.2は全員1月として誕生月の追加調査を避ける。
2. 日常イベントの発生数（約64件/70年）が多すぎないか。**推奨案:** 月3%＋年1回55%から始め、テスト後に年40〜60件へ下げる。
3. 通貨の表記・開始金・年収表。**推奨案:** 表示を貫、1貫＝1000文、開始金4〜20貫、年収2〜60貫の仮値から残高を見て再調整する。
4. 家柄を固定し、成長対象外とするか。**推奨案:** 能力というより出自の札として固定する。
5. 老齢期の能力衰えを入れるか。**推奨案:** 恒常的な能力低下は採用せず、70歳以降の成長逓減と健康リスクのみ入れる。
6. 健康の数値を常時表示するか。**推奨案:** 数字ではなく状態語を表示し、画面を過密にしない。
7. 健康由来の早死にを史実没年前にも許すか。**推奨案:** 第2弾初期は早期死亡を明示的な危険選択に限定し、自然な死亡乱数は史実没年以降にする。
8. 役職を人物固有名称まで表現するか。**推奨案:** 内部は共通5段階、表示は第1弾では抽象名。史実確認後に人物別名称を足す。
9. 月次ランダムイベントと年次行事の頻度。**推奨案:** 30件の内容を作っても選択疲れが出る可能性があり、初回計測で頻度を優先調整する。
10. 判定に固定基準値方式を採用するか。**推奨案:** 固定難易度とし、成長による再現可能な上達を見せる。
